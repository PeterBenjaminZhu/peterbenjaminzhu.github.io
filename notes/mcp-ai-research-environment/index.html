MCP 与 AI 辅助科研工作环境

2026年11月12日·2 分钟·

1. MCP 是什么？
#

MCP（Model Context Protocol，模型上下文协议）是一套让 AI 应用以统一方式连接外部工具、数据和服务的开放协议。

可以把大语言模型看成“大脑”，把 MCP 看成它连接外部世界的标准接口。借助 MCP，ChatGPT、Codex 或其他 AI 应用可以在授权范围内访问或调用：

  • 本地文件与项目资料；
  • 数据库、代码仓库和内部系统；
  • 文献管理、日历、邮件与协作工具；
  • Wolfram、LaTeX、数值计算等专业软件。

它的价值在于减少重复适配：工具只需实现一次 MCP 接口，不同 AI 应用便可以按统一方式发现和调用它。

2. MCP 的基本结构
# 

用户
  ↓
AI 应用（Host，例如 ChatGPT、Codex、IDE）
  ↓
MCP Client
  ↓
MCP Server
  ↓
文件 / 数据库 / GitHub / Wolfram / Zotero / 其他服务
  • Host：运行 AI 的应用。
  • MCP Client：负责发现工具、传递参数并接收结果。
  • MCP Server：把某项外部能力封装为可调用的工具。

MCP 可以提供只读能力（如搜索文献、读取文件），也可以提供写入或执行能力（如创建任务、修改代码、运行计算）。后者应始终受到明确权限和人工确认的约束。

3. MCP、插件与 RAG 的区别
#

概念 主要解决的问题 作用
MCP AI 如何连接并调用外部世界？ 标准化工具与数据连接
插件 AI 如何接入某个特定产品能力？ 通常是某平台或厂商的集成方式
RAG AI 如何从资料中找到相关知识？ 检索、筛选并补充上下文

两者并不冲突。一个研究型工作流中，RAG 可以帮助从论文库中找相关材料，MCP 则可以让 AI 读取资料、调用计算工具、编辑 LaTeX 文件或管理参考文献。

4. ChatGPT 在研究工作中的典型用法
#

对于理论物理、数学、计算或代码研究，MCP 可以将多个步骤连成一个连续工作流：

研究问题
  ↓
检索本地笔记与文献
  ↓
阅读已有推导和未解决问题
  ↓
调用 Wolfram 或其他工具进行符号/数值检验
  ↓
记录结论与依据
  ↓
整理进 LaTeX 论文草稿

例如，可以让 AI：

  • 根据本地笔记继续某一段推导；
  • 比较论文原文、自己的理解和已有计算；
  • 对符号计算结果作交叉检查；
  • 将已确认的结论与待验证的猜想分别记录；
  • 在用户确认后，将成熟内容移入论文正文。

5. README.md：项目介绍，也是协作入口
#

GitHub 中常见的 README.md 主要面向项目使用者和合作者，用于说明项目是什么、如何安装、如何运行以及如何引用。

在 AI 辅助研究项目中，README.md 还可以承担另一层职责：为人和 AI 提供项目的共同入口。它应让新进入项目的人或 AI 快速知道：

  • 研究目标与范围；
  • 当前处于什么阶段；
  • 关键背景资料和参考文献；
  • 文件夹各自负责什么；
  • 重要的符号、约定或边界条件；
  • 下一步需要解决的问题。

因此，二者的联系是：它们都是项目的 Markdown 说明文档；区别是 AI 研究工作流中的 README 更强调“如何持续推进这个项目”，而不只是“如何使用这个项目”。

6. AGENTS.md：给 AI 的工作约定
#

如果 README 回答“这个项目是什么”，那么 AGENTS.md 更适合回答“AI 在项目中应怎样工作”。例如：

# AI 工作约定

## 推导规范
- 所有新符号首次出现时必须定义。
- 明确区分已证明结论、数值证据与猜想。
- 关键公式需要进行量纲、符号或极限检验。

## 文档规范
- 中间推导先写入 derivation/，不要直接改论文正文。
- 已确认的决定记录在 notes/decisions.md。
- 引用资料时保留可追溯来源。

## 工具规范
- 对符号计算给出可复现的输入与结果摘要。
- 修改最终稿前先说明变更内容并等待确认。

这类约定能减少上下文丢失，也能让研究过程更容易复查。

7. 推荐的简洁研究项目结构
#

不必从复杂系统开始。对于持续数周或数月的研究，可采用如下结构：

Research_Project/
├── README.md              # 研究目标、现状与项目导航
├── AGENTS.md              # AI 协作规则与质量要求
├── 00_inbox/              # 待整理论文、聊天记录和原始材料
├── 01_background/         # 背景知识与文献笔记
├── 02_derivation/         # 中间推导、计算记录、代码与检查
├── 03_results/            # 已确认结果、图表和数据
├── 04_paper/              # 论文或正式输出的 LaTeX 源文件
└── 05_archive/            # 历史版本与不再使用的材料

其中最重要的分界是：

原始材料 → 中间推导 → 已确认结果 → 正式论文

将未验证的尝试与正式结论分开，能避免把草稿、猜测或临时计算误写进最终论文。

8. 是否应该先写 README？
#

  • 一次性的短问题或单个公式推导：不必专门建立完整项目结构。
  • 论文、毕业课题、长期研究方向或反复迭代的计算项目：建议在开始时写一个简短 README。

README 不需要完美。先用十分钟写清“目标、当前问题、材料位置、下一步”即可；随着研究推进，再逐步补充符号约定、已确认决定和工作流程。

9. 最小可用 README 模板
# 

# 项目名称

## 研究目标
用一两句话说明要解决的核心问题。

## 当前阶段
- 已完成：
- 正在进行：
- 下一步：

## 重要约定
- 单位制、度规符号或其他通用约定：
- 已确认的边界条件/假设：

## 项目导航
- `01_background/`：背景与文献笔记
- `02_derivation/`：中间推导与计算验证
- `03_results/`：已确认结果
- `04_paper/`：正式论文草稿

## 关键参考
- 文献或资料的可追溯信息

结论
#

MCP 的核心意义，是让 AI 从单纯的问答工具变成能够在授权范围内读取资料、调用专业软件并参与实际研究流程的协作助手。对于长期研究，建立清晰的目录、README 和 AI 工作约定，比一开始追求复杂自动化更重要：它们能保留研究上下文，使每一次协作都能从已有进展继续，而不是重新开始。
